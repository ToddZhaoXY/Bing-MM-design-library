## 3. Spectrum 真正值得继续借鉴的点

1. **文档不只展示外观，也帮助做决定。** Accordion 在 Anatomy、Component options 之外，分别说明 States、Behaviors、Usage guidelines；使用指导包含渐进披露以及不宜过度使用折叠的情况。
2. **阅读内容与展示内容有不同的节奏。** 参考页在说明区用小标题、短段落及分组表达不同议题，而不是让所有说明都成为一条长行。这里应借鉴阅读组织，不是机械复制它的列数。
3. **复用入口和上下文明确。** 参考页有 Code available、Copy code、Go to RSP、Copy markdown，说明“看到什么”和“接下来能做什么”。我们的 Figma／Mosaic／HTML／SDL 具有不同用途，应保留自己的来源体系。
4. **长文档的操作有可发现性。** 参考页有 Skip to main content，以及属性表的滚动说明。我们的基础交互已有不少实现，下一步应补容易忽略的阅读和键盘入口。

结论：当前外层视觉方向已经接近参考站。下一轮不宜只围绕圆角、阴影、图标继续反复修改；更有价值的是阅读、选型和复用的完整性。

## 4. 优先修改建议

以下全部是建议，尚未修改现有网页。

### P1-A：把局部限宽升级为文档说明的统一规则

**当前证据**

- `.variant-intro p` 仍以 `max-width:none` 为基础规则。
- 最新限宽只针对 Sectional Nav 的 `#variantDescription` 和首页 Component Source 介绍，并未覆盖所有长说明。
- 浏览器中 Algo Block 的 Standard 说明仍横跨很长的一行；Sectional Nav 的说明则已经是较易阅读的短段落。

**建议**

- 长介绍、变体说明和使用指导采用统一的阅读宽度，例如先试 60–75ch，并以实际字体和文本复核。
- 标题、正文与预览的左边缘仍对齐；不把整个主内容、预览、表格或 Figma 组件一起缩窄。
- 短操作提示不强制拉成固定宽度；手机使用可用宽度，避免额外左右缩进。

**验收**：在 Intro、Algo Block、Sectional Nav、一个 Cell 上确认长段落换行更自然，预览内部尺寸和布局不变。

### P1-B：属性表应能读完内容，而不只保持整齐

**当前证据**

- Algo Block 的长 Default 值显示省略号。
- `library-properties.js` 把完整值放入原生 `title`；`styles.css` 将 Default 的代码强制为单行省略。这不是数据丢失，但鼠标悬停以外缺少明显的查看全文入口。
- 390px Deeplink Item 中，Properties 的 Default 列位于横向可视区以外；表格可以横向滚动，但画面没有明确的滚动提示。
- 表格中的 `Type` 多处实际表示预览控件类型，例如 `select`；`free text` 也没有解释字段用途。不能把它直接当成正式组件 API 文档。

**建议**

- 为长默认值提供可用键盘和触摸操作的展开／查看全文方式，或允许适度换行；不要截断源数据。
- 明示“横向滚动查看全部列”，并保留已有可聚焦滚动区域。
- 区分“预览选项”和“正式 API 属性”。增加简短用途说明时，必须来自已有设计／实现依据；不伪造类型、默认值或接口。

**验收**：键盘和触摸都能读取完整默认值，手机能够发现剩余列，表格不会带动整页横向溢出。

### P1-C：代码区要说明来源，并减少无效阅读负担

**当前证据**

- Algo Block 初始展示为多层原始 SDL JSON，首段主要是嵌套结构，内部也包含图片数据。
- `applyMosaicSDL()` 已记录 `data-format`，并设置可访问名称来区分 SDL 与 HTML，但普通页面缺少一致、可见的格式／来源标签。
- Cells 有可见 HTML 标签；Sectional Nav 已说明 `Main result + deeplinks · SDL`，证明不同来源和覆盖范围确实存在。
- 代码区已有最大显示高度及局部滚动，不能把它描述为“整份源码无限撑高页面”。

**建议**

- 统一显示：HTML／原始 SDL／派生 SDL，以及“完整组件”或“局部来源”等覆盖范围。
- 可试紧凑代码摘要加“展开代码”，或保留现有高度并增加明确的展开入口；完整源码随时可查看。
- Copy 按钮明确复制的是 HTML 还是 SDL；源码缺失时给出真实说明。
- 若简化显示图片数据或嵌套结构，仅改变阅读视图，不修改保存的原始 SDL，不偷偷改变复制内容。

**验收**：使用者能在点击复制前知道格式和覆盖范围；实际复制结果与标记一致；原始 SDL 逐字保留。

### P1-D：从“展示组件”补齐为“帮助选择和正确使用组件”

**当前证据**

- 19 页标题结构已检查。Organisms 以 Overview、Anatomy、Properties、Example 为主；Cells 以 Overview、Properties、Used in 为主。
- 现有变体介绍和 Example 已有部分交互说明，Expansion 也有 Fallback logic；不是完全没有说明。
- 但尚无统一的 Usage guidelines／Behaviors 文档结构，难以快速比较“何时用、何时不用、与另一个组件有什么区别”。

**建议**

- 先为一个 Organism 试点，不一次性给所有页面加空章节。
- 内容优先覆盖：适用任务、与相邻类型的区别、内容过长／缺图／展开时如何处理、真实支持的交互。
- States 可以先区分“设计有定义”“当前演示可操作”“尚未确认”，不要因为参考站有某状态就给 Algo 添加未经确认的 Disabled／Error 状态。
- 需要新设计决策的规范先标“待确认”，不能只从演示代码推导为产品标准。

**验收**：设计师不操作所有下拉框，也能解释选择该组件或变体的理由；已知行为与演示一致，未确认部分明确标识。
